# 全屋报价器（portal/quote.html）逻辑说明

目标：员工操作简单、不漏装修细节、不漏项目、不算错价。

## 员工只做 4 步
1. **房间尺寸**：加房间（客厅/卧室/厨房/卫生间/阳台/走廊），只填长、宽、层高、门窗、点位、柜长等“量出来的数”。
2. **必答问题**：11 道全屋问题 + 每个卫生间“是否移位”、每个阳台“是否封窗”，每题必须选“是/否”。
3. **核对清单**：系统按施工顺序（8 个工序）自动生成全部项目和数量，每项都写着算法（如 `周长44×层高9 − 门洞1×21 = 375`）。
4. **报价单**：通过检查后才能打印/保存 PDF。

## 为什么不会漏项
- 项目不是员工一条条勾出来的，而是**由房间 + 问题自动生成**：有卫生间就一定有防水、找坡、地漏、挡水条、美缝；有插座点位就一定有面板；有地柜就一定有台面；新砌墙自动加两面批灰+油漆；动承重墙自动加工程师签字；垃圾清运车次按拆除量自动算。
- 必做项（防水、油漆、保护、清运、开荒等）关掉必须写原因。
- 检查会提示：房间面积合计比套内面积少 15% 以上（可能漏走廊/储物间）、厨房没地柜、卫生间没马桶、配套项被关掉等。

## 多层房屋（排屋/独立屋）
- 第①步选“房屋有几层”，每个房间选“在几楼”，房间按楼层分组显示，清单里显示为「2楼·主卧」。
- 自动加：材料搬运上楼（楼上面积 × 所在楼层−1，必做）。
- 多出 2 道必答题：楼梯（踏步砖、扶手栏杆、楼梯灯+双控开关）、挑空（脚手架高空作业）。
- 检查：某一层没有房间 → 红色；楼上没有卫生间 → 提醒。

## 专业报价单（2026-09 升级）
- 每个项目拆成 **主材 + 辅材 + 人工**，主材单价已含损耗；**合价 = 数量 × 单价**。
- 每个项目带 **工艺做法及材料说明**，印在客户报价单上（防扯皮）。
- 报价单可 **按房间** 或 **按工序** 排列，每组有小计；底部有客户/公司签名栏。
- 新建报价先选模板：公寓整装 / 排屋整装 / 厨卫翻新 / 空白。
- 新增细项：开工放线、拆旧天花、铲旧墙皮、铲砖后找平、配电箱更换、空调/热水器专用回路、水管打压、闭水试验、
  窗台石、下水管包封、灯带、排气扇、卫浴五金、浴室镜、鞋柜、电视柜、防盗铁花、门廊户外砖、外墙漆。
- 可导出 Excel（CSV），可打印 A4 横向。

## 为什么不会算错
- 面积/周长/墙面积/踢脚线全部由尺寸公式计算，员工不用心算。
- **员工不能在清单里改单价**，单价统一来自价目表；本单改过价会被标黄。
- 手动改数量必须写原因，和自动数量相差 30% 以上会提醒。
- 每行先四舍五入到整数 RM 再加总，明细加起来一定等于总数；付款节点最后一期 = 总价 − 前几期，保证分毫不差。
- 优惠超过设定比例（默认 5%）必须填审批人；付款比例加起来必须 100%。

## 待老板确认
- 价目表里的单价是**示例价**（沿用旧演示版），需要换成公司实际价格（改 quote.html 顶部 PRICE）。
- 付款节点比例（默认 30/30/30/10，分别挂在签约、水电验收、泥水验收、竣工）。
- 以后可把价目表搬到 Supabase，老板改一次全员生效；报价单也可一键转成 OMS 订单。

## 马来西亚空间与平面图导入（2026-09-26）
- 空间分组：起居与卧室、厨卫与家务、交通与户外；细分客厅、餐厅、家庭厅、主人房、干厨、湿厨、玄关、书房、储物间、走廊、车廊、后院、侧院及楼梯。
- 内部楼层编码保持兼容：1=底层 Ground Floor，2=一楼 First Floor，3=二楼 Second Floor，4=三楼 Third Floor。
- 干/湿厨沿用厨房计算，主人房沿用卧室计算；车廊/后院/花园/楼梯仅记录尺寸，施工数量在全屋必答问题中填写。它们不生成室内地砖、墙漆、天花等，也不进入室内面积及材料上楼面积，防止重复计价。
- 本地识别启动：Mac 上运行 `python3 scripts/quote-plan-server.py`，或双击 `scripts/start-quote.command`。打开 `http://127.0.0.1:8766/portal/quote.html`。已有 `file://` 页面也可连接此服务；浏览器如请求本地网络权限需允许。
- 不同地址的浏览器草稿独立保存。原 `file://` 草稿继续在原文件地址打开，不会自动搬到 localhost。
- 上传 PNG/JPG/WebP/PDF，最大 20 MB，PDF 最多 12 页。使用 macOS Vision 本机 OCR，无需 API key，图纸不上传外部服务，临时文件处理结束即删除。
- **识别边界**：这是文字标签识别，不是完整的 AI 建筑图几何解析。读取房间标签、同一标签行明确标注的长×宽及单位（mm/cm/m/ft），缺失尺寸和层高留空；同页多楼层不猜测归属，不从墙线/比例尺推算，不自动识别设备点位。复杂图纸需要人工输入，未来可接视觉模型。
- 识别结果先编辑/取消勾选，核对后才追加房间；不覆盖已有报价。追加后不再展示同批候选，避免连续点击重复添加。
- 图纸房间的点位、门窗、柜体和设备数量留空，不用模板数量冒充识别结果；做法沿用类型初值，必须逐房间确认施工范围才能出单。编辑尺寸、做法或楼层会撤销确认。
- 原品牌/型号/主材自定价修改保留。

- 是=实际填写级数、梯宽、踏面深度、级高；选择瓷砖/木饰面/石材/其他材料，填写规格及厚度，明确立面处理、前沿收口、防滑、基层处理。
- 瓷砖细分平铺/前沿下挂，下挂需填写高度；木饰面分实木、多层复合、SPC/LVT配套系统；石材选择具体材质，其他材料补充名称做法。
- 平台面积、扶手长度、楼梯灯及双控套数独立填写，不做填0，不再默认16级/14尺或自动配整套灯。
- 选型进入报价和导出；木/石/其他面层及平台新增价格待核定项目，零价时阻止正式出单，不沿用瓷砖单价冒充实际报价。所有默认价仍须核对选定工艺。
- 验证：保留现状无计费、砖木分项、下挂说明及旧字段排除、未核价提示、平台/扶手/灯数量、单层不生成；浏览器实测下挂展开高度输入。

### 每空间手绘量尺辅助（2026-10-17）
- 每个房间独立保存底图、轮廓顶点、单位和实测数据。图片上传仅作描图底图，不做手写数字OCR或图片比例测量；JPG/PNG/WebP先压缩，随本机报价保存。
- 画板逐点点击或触摸连线。直角模式按方向输入每条实际边长，闭合误差不自动摊配；坐标模式输入同一正交基准下的实测X/Y，适用于含斜边的简单多边形。
- 最多40个顶点、单一外边界；不支持圆弧、内部孔洞。重复点、相交、零面积、缺尺寸均阻止应用。
- 点击确认后，面积与周长覆盖矩形计算，沿用地面/天花面积、墙面周长×层高及门洞原有扣除规则；不同施工范围仍用单项实际工程量覆盖。该功能没有改变原有门窗扣除政策。
- 开始画轮廓或修改量尺数据后，未确认的轮廓不按原长宽误算；正式报价检查提示重新确认。取消应用可保留草图并显式恢复长宽计算。
- 价目匹配逻辑不变，规格缺价仍待报价。所有图片和量尺数据仍为本机浏览器数据，未新增服务器同步或发布。

### 手绘现场误差处理（2026-10-18）
- 手绘像素只提供大致水平/垂直方向；允许线条偏斜，最后一边的小偏差吸附闭合。较大缺角自动补一个直角顶点，并要求补填新增边的实测长度。
- 边长填写完成后按实测尺寸重绘轮廓；不闭合时显示横向、纵向差值和红色虚线，不显示可报价面积。
- 合计闭合差不超过20mm时，尝试对各轴最长有效边给出具体建议值；候选须通过闭合及简单多边形校验。不静默改数，用户二次确认后记录原值、新值、单位及时间，且仍须确认应用。
- 超过20mm不提供调整，不平均摊差。阈值为产品默认提醒规则，不作为施工测量精度或验收规范。
- 明确提供“保存草图”；未闭合和未确认均可保留本机草稿，仍阻止正式报价使用。

### 图上点位与重复字段（2026-10-18）
- 进入手绘模式后隐藏重复的矩形长宽字段，显示待确认或已应用的面积/周长；恢复长宽模式才重新显示。
- 确认轮廓后，在图上操作选择灯、水、电或删除点位；标记仅为位置示意，不代表施工距离。
- 点位先作草稿，点击确认数量后覆盖lights/wpts/pts并隐藏重复数量字段；不自动选择收费项目。原手填数量保留以便取消联动恢复。
- 联动后修改点位或轮廓，必须重新确认数量；否则正式报价检查阻止通过。图纸上传仍不具备自动拆分空间轮廓的能力。
- 已填写点位数量可用“把已填写的灯／水／电数量带到图上”生成待定位标记；保留已有位置，仅为缺少的数量建立未定位记录。图内显示已填数量和待定位总数，不按数量猜测位置。选择类型后逐个点击定位；点位加编号。数量减少涉及移除标记时须确认。每空间上限200个，非负整数。
