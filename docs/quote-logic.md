# 全屋报价器（portal/quote.html）逻辑说明

目标：员工操作简单、不漏装修细节、不漏项目、不算错价。

## 员工只做 4 步
1. **房间尺寸**：加房间（客厅/卧室/厨房/卫生间/阳台/走廊），只填长、宽、层高、门窗、点位、柜长等“量出来的数”。
2. **必答问题**：11 道全屋问题 + 每个卫生间“是否移位”、每个阳台“是否封窗”，每题必须选“是/否”。
3. **核对清单**：系统按施工顺序（8 个工序）自动生成全部项目和数量，每项都写着算法（如 `周长44×层高9 − 门洞1×21 = 375`）。
4. **报价单**：通过检查后才能打印/保存 PDF。

## 为什么不会漏项
- 项目不是员工一条条勾出来的，而是**由房间 + 问题自动生成**：有卫生间就一定有防水、找坡、地漏、挡水条、美缝；有插座点位就一定有面板；有地柜就一定有台面；新砌墙自动加两面批灰+油漆；动承重墙自动加工程师签字；垃圾清运车次按拆除量自动算。
- 必做项（防水、油漆、保护、清运、开荒等）关掉必须写原因。
- 检查会提示：房间面积合计比套内面积少 15% 以上（可能漏走廊/储物间）、厨房没地柜、卫生间没马桶、配套项被关掉等。

## 为什么不会算错
- 面积/周长/墙面积/踢脚线全部由尺寸公式计算，员工不用心算。
- **员工不能在清单里改单价**，单价统一来自价目表；本单改过价会被标黄。
- 手动改数量必须写原因，和自动数量相差 30% 以上会提醒。
- 每行先四舍五入到整数 RM 再加总，明细加起来一定等于总数；付款节点最后一期 = 总价 − 前几期，保证分毫不差。
- 优惠超过设定比例（默认 5%）必须填审批人；付款比例加起来必须 100%。

## 待老板确认

- 付款节点比例（默认 30/30/30/10，分别挂在签约、水电验收、泥水验收、竣工）。
- 以后可把价目表搬到 Supabase，老板改一次全员生效；报价单也可一键转成 OMS 订单。
