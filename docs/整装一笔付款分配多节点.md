# 整装一笔付款分配到期款和增项

适用于所有整装项目。原合同期款与客户已签署的增项各保留自己的付款节点和余额。一笔实际转账可以同时支付多个节点，但银行进款只登记一次。

例如第 3 期还差 RM 50,000，已签署增项还差 RM 8,000，客户转账 RM 58,000：员工登记一笔 RM 58,000 的银行收款和一个真实参考号，归款明细分别填“第 3 期 RM 50,000”和“增项 RM 8,000”。整单已付增加 RM 58,000；两个节点分别增加对应已付金额。部分付款同理，员工按与客户确认的归款金额填写，不自动猜测优先顺序。

## 操作与约束

- 员工在“实际收款与付款进度”勾选“一笔转账同时支付多个期数／增项”，输入真实到账总额、日期、方式、参考号，再填写至少两个节点的归款金额。各明细之和必须等于真实进款；参考号只登记一次。
- 增项需先由客户签署。待签或已作废增项不能收款，单个节点不能超收。
- 现金仍待店长核对；核对前在各节点显示待核对，不计入已付。退款可按多个节点拆分；作废一笔进款会撤销它的全部归款，若造成退款超过收款则拒绝。
- 历史单节点进款保持原样，不自动改写。客户可看见归款金额与节点，不接收银行参考号或员工内部备注。
- 已经收到的一笔合并转账，应使用此功能登记一次。不要伪造两笔银行进款或把同一笔金额重复计算。

## 上线顺序

1. 在现有整装付款、增项和签署迁移都生效后，执行 `supabase/renovation_payment_allocations_migration.sql`。可重复执行，不改写已有进款。
2. 确认数据库函数和模拟检查通过，再发布 `portal/renovation/finance-staff.js` 与 `finance-view.js`。
3. 用无真实客户资料的测试项目核对：一笔转账分配到原合同与已签增项、客户页金额一致、参考号不重复、现金待核对、拆分退款和作废限制。上线前不要把未部署的新前端单独推到线上。
