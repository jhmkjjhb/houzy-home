# 新增单客户电子签署与门店业绩

## 新增单签署流程

1. 店员创建新增工项或材料单，保存后状态为“待客户签署”。待签单不计入应收，不生成执行单，不允许按该节点收款或归期。
2. 店员点击“复制客户签署链接”，自行发给业主或其授权签署人。系统只复制，不自动发送消息。链接绑定项目和单条新增单，不需要客户输入查阅码。
3. 客户打开专属链接，核对名称、规格、数量、单价、金额、付款节点和确认后项目总额，填写姓名、手写签名并勾选同意。
4. 后端校验签署凭证、当前内容摘要和有效笔迹后，锁定签署明细，记录姓名、服务器时间、手写笔迹及完整签署快照的SHA-256摘要。签署成功才计入应收、生成执行单和收款节点。
5. 已签确认单只读，可打印或保存PDF；不得覆盖签署内容。金额发生变化需撤销／重新建立新增单并重新签署。撤销已签单仍受收款、退款和执行状态限制，保留原签署记录。

手机号查询保留直接查看项目的方式，但只读列表不会下发专属签署凭证或手写笔迹。电子签署不等于短信认证或第三方实名认证，不对签署人身份作额外认证承诺。

空白／笔迹过少、错误项目或签署凭证、未同意、过期内容摘要均被拒绝。重复提交相同签名只生效一次；其他人或不同签名不能覆盖已签内容。还有待签新增单时不能完成项目验收。

上线前若发现已生效但未签署的历史增项，迁移会停止，需先核对收款及执行情况，不静默降低已有应收。

## 门店业绩

员工后台“经营报表 → 门店业绩（商品＋整装）”及首页净收款卡片采用统一汇总：

- 商品已确认收退款流水；未核对现金不计入。
- 整装已确认收款减已确认退款，包含原合同和已签增项的分笔进款，只统计实际流水，不按合同总额或付款计划统计。
- 角色、门店、区域和员工归属均在服务端隔离。店员看自己的项目，店长看本店，区域负责人看本区域，管理层看授权全局。
- 按马来西亚日期过滤收退款日。不同币种分开统计，不进行汇率换算。
- 现有旧商品单存在“已付清”但无流水的记录。默认沿用原金额并单列为历史标记，日期按开单日；报表可以关闭该项。后续补录流水后不再重复计入。不会自动伪造收款记录。
- 整装SST、发票和员工提成不在本次门店实收合并中自动推定或发放，仍由各自业务规则核算。原商品经营指标标明原商品口径。

## 部署与验证

在现有整装增项结构后，依次应用 `renovation_addition_signatures_migration.sql`、`store_performance_renovation_migration.sql`，再发布对应网页及模块。

`tests/renovation-signatures-performance.mjs` 验证最终结构的签署门槛、私有凭证、笔迹校验、内容变更、签署不可覆盖、重复提交、执行及收款激活、店面业绩汇总、退款、历史标记、币种和跨店权限。

`tests/fixtures/renovation-signature-performance-smoke.sql` 使用无真实客户身份的模拟项目，签署、收退款及店面业绩差额验证全部在事务内回滚。旧的未要求电子签名的增项测试仅用于历史迁移回归，不代表当前上线行为。

## 2026-10-25 业绩与收款日期规则

- 已取消的商品订单：其收款不计入商品净收款、合计净收款和待核对现金，单独列为“已取消订单收款（待核对退款）”，CSV同步导出。原商品订单尚无退款流水，需人工核对是否已退款。
- 整装收退款日期：不得早于签约日前30天（允许签约前收取订金）；日期在上个月或更早时，只能由店长或上级登记，并在内部备注写明原因，避免改动已结算月份的业绩。
- 收退款参考号在所有整装项目之间唯一（不分方式和大小写）。
- 按业务负责人决定保持不变：客户凭登记手机号即可查看已确认合同；店长登记的现金仍直接计为已核对。
