# 整装实际收款与客户付款进度

店员在整装主单的“实际收款与付款进度”登记真实收退款，客户在同一项目的“我的付款进度”查看合同总额、已确认净付款、尚未付清、付款状态和工程状态。客户支持手动刷新及每30秒自动刷新；工程清单默认折叠，可点击标题展开。

## 记账规则

- 合同付款节点只是计划，不自动生成实际收款。现有项目不回填、不推断历史付款；须核对凭证后补登。
- 电子方式（银行转账、电子钱包、刷卡）登记后计入已收；员工登记现金须店长或上级核对。店长登记现金视为已核对。
- 已确认净付款＝已确认收款－已确认退款；尚未付清＝锁定合同总额－已确认净付款。待核对现金单列，不算已付款。
- 收款需实际金额、收款日期、银行参考号或收据编号。同项目同类别及方式不能重复使用有效参考号。
- 退款仅店长或上级可登记，不得超过净收款。错误记录由店长填写原因作废，保留原始记录和审计；作废不是向客户退款。
- 合同草稿不能收款；收款（含待核对现金）不得超出合同总额，退款和作废不得导致余额异常。
- 收款不会自动确认签约、推进履约、完成验收或启动质保；这些业务状态分别管理。

## 权限与同步

`renovation_payments` 按原整装项目的门店、区域及创建人范围隔离；禁止客户端直接增删改，全部写入走 `renovation_payment_command`。写入锁定项目行、检查版本并写审计；重复请求编号及相同内容只记一次。

员工读取 `renovation_payment_view`，客户读取 `renovation_customer_payment_view`，两者调用同一付款汇总，避免出现两套金额。客户不接收内部备注、员工身份、银行参考号、完整内部快照及厂家成本。

## 上线

在已有整装数据结构上执行 `supabase/renovation_payments_migration.sql`，再发布网页与 `finance-view.js`、`finance-staff.js`、更新后的客户和员工脚本。迁移可重复执行，不更改历史合同，不写入任何真实收款。

部署检查使用无真实客户身份的模拟项目，收款、退款及权限检查全部放在事务内并回滚，不留测试项目或付款。

## 验证

`RENO_PGLITE_MODULE=/path/to/pglite/dist/index.js node tests/renovation-payments.mjs` 验证重复迁移、付款计划不计实收、金额及日期、现金核对、退款、作废、重复请求、超额收款、版本冲突、跨店权限、客户与员工金额一致和生产回滚测试脚本。

浏览器模拟验证店员登记刷新余额、退款权限、客户刷新金额及工程状态、清单展开／收起和390px手机布局。

## 尚未接入

整装收款使用独立台账，不写入有商品订单外键的旧 `order_payments`。原商品销售报表、税务发票、银行自动对账和支付网关尚未接入，不能将本功能宣称为已完成这些功能。
