# 客户整装改版发布说明

本分支从最新main隔离，仅包含五章节客户界面、客户工程进度只读接口，以及界面必需的增项电子签署依赖。报价、商品订单、公司授信、员工绿金工作台改版和门店业绩报表不在本分支范围。

## 数据库先行

现网应已有整装主单、收退款、分期与增项基础迁移。部署前备份相关函数和增项数据，再依次应用：

1. `supabase/renovation_addition_signatures_migration.sql`
2. `supabase/renovation_rpc_permissions_migration.sql`
3. `supabase/renovation_customer_progress_migration.sql`

若已有生效但未签署的历史增项，签署迁移会停止。应核对真实收款和履约记录后制定历史数据处理方式，不能跳过保护或伪造客户签署。不要先发布前端再处理此项。

新建增项保存为待客户签署，不计入应收、不生成执行单、不能收款。员工复制专属签署链接后自行交给业主；客户核对并填写姓名、笔迹和勾选同意后生效。普通手机号查阅链接不下发签署凭证。已有签署凭据不可覆盖。

工程进度接口只读，排除作废执行单和未签增项，不返回负责人、客户手机号、内部日志或签署凭证。原合同和增项电子签署的权限模型不变。

## 前端

数据库验收后发布本分支的客户HTML、客户样式和脚本、增项与付款相关共用脚本、员工整装HTML和最小配套脚本改动、Service Worker。客户旧项目链接继续有效，专属增项链接直接打开签署章节。导览只切换视图；付款登记、完成工程及确认验收仍由门店操作。

## 验证

本分支增加 `tests/renovation-signatures.mjs`、`tests/renovation-customer-progress.mjs`、`tests/renovation-signing-input.cjs` 和 `tests/renovation-customer-browser.cjs`。原收退款测试保留为历史迁移回归，不代替最终签署结构测试。

PGlite数据库测试使用 `RENO_PGLITE_MODULE` 指定模块路径；Chrome浏览器测试使用 `PLAYWRIGHT_MODULE` 和 `RENO_BASE_URL`。浏览器测试会隔离全部业务接口，不能替代生产数据验收。

本次为代码推送，不自动执行正式数据库迁移、不合并主分支、不声称已完成生产上线。
