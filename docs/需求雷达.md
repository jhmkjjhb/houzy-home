# 需求雷达

员工后台入口：`portal/lead-radar.html`（侧边栏“需求雷达”）。

每天 08:00–22:00（马来西亚时间）每 2 小时自动搜索新山的公开装修求助帖，AI 过滤同行广告并评分，员工到原帖回复，引导客户主动 WhatsApp HOUZY。

## 做什么、不做什么

- 只用 Firecrawl 搜索接口返回的标题和摘要，不打开、不抓取 Facebook 等平台页面，不登录任何账号。
- 不自动回复、不群发。建议回复附 HOUZY WhatsApp 链接，链接预设文字带 `[Radar-xxxxxx]`，客户发来的第一句话就能看出来自哪个帖子。
- 帖子里的号码只在 AI 判断为真实需求、且客户明确邀请承包商联系时保存；号码从帖子原文提取，不采用 AI 生成的号码。每个帖子只能“WhatsApp 联系”一次，数据库强制执行。
- 未转客户的帖子 90 天后自动删除。
- 实际效果：2026-10-25 试跑 4 组关键词共 40 条结果，真实需求约 2–3 条，其余多为同行广告。它是补充渠道，不能替代广告。

## 组成

| 文件 | 作用 |
|---|---|
| `supabase/lead_radar_migration.sql` | 3 张独立表（关键词、运行记录、帖子）、RLS、`lead_radar_mark` 标记状态、`lead_radar_can_run`、`lead_radar_purge`，并写入 20 个三语关键词。可重复执行，不涉及订单、合同和客户表 |
| `supabase/functions/lead-radar/` | `index.ts` 运行流程；`logic.ts` 去重、来源识别、日期、号码、AI 结果校验 |
| `supabase/lead_radar_schedule.sql` | 08:00–22:00（马来西亚时间）每 2 小时搜索并分析；每次 20 分钟后补分析剩下的帖子，不花搜索积分 |
| `portal/lead-radar.html`、`portal/lead-radar/` | 员工页面 |

权限：在职员工都能查看和标记；总经理、管理员和超级管理员可以改关键词、手动运行。员工不能直接改帖子和 AI 结果。

## 部署步骤

1. **申请密钥**：Firecrawl API Key（firecrawl.dev）、OpenAI API Key（platform.openai.com）。自己生成一个随机字符串作为 `RADAR_CRON_SECRET`，例如在终端执行 `openssl rand -hex 32`。
2. **数据库**：在 Supabase SQL Editor 执行 `supabase/lead_radar_migration.sql`。
3. **函数密钥**：Supabase 后台 → Edge Functions → Secrets，添加：
   - `FIRECRAWL_API_KEY`、`OPENAI_API_KEY`、`RADAR_CRON_SECRET`（必填）
   - `OPENAI_MODEL`（可选，默认 `gpt-6-luna`，2026-10-26 OpenAI 官方列表中标为高量低成本任务的模型）
   - `RADAR_MAX_QUERIES`（可选，默认 25，最多 50）
   - `HOUZY_WHATSAPP`（可选，默认 `60105898786`）
   `SUPABASE_URL`、`SUPABASE_SERVICE_ROLE_KEY`、`SUPABASE_ANON_KEY` 由 Supabase 自动提供。
4. **部署函数**（关闭平台 JWT 校验，函数自己校验调用者）：
   `supabase functions deploy lead-radar --no-verify-jwt --project-ref csabbxiijzghooppayae`
   没有命令行时，可在 Supabase 后台新建函数 `lead-radar`，粘贴 `index.ts` 和 `logic.ts` 两个文件，并关闭 “Enforce JWT verification”。
5. **首次运行**：用总经理账号打开需求雷达，点“立即运行一次”，确认运行记录为“完成”或“部分完成”，并抽查几条 AI 判断。
6. **定时任务**：把 `lead_radar_schedule.sql` 里的占位符替换成步骤 1 的 `RADAR_CRON_SECRET`，在 SQL Editor 执行。替换后的内容不要保存到仓库。
7. **发布网页**：合并到 `main`，GitHub Pages 自动发布。

## 费用控制

- 每个关键词每次搜索约 2 个 Firecrawl 积分；20 个关键词每次约 40 积分，每天 8 次约 320 积分，每月约 9,600 积分（2026-10-27 起）。积分用完后运行记录显示失败，需升级 Firecrawl 套餐。
- 每次运行最多搜索 `RADAR_MAX_QUERIES` 个关键词、最多分析 120 条待分析帖子；15 分钟内不能重复运行。
- 免费版 Supabase 函数最长 150 秒。函数 120 秒后不再开始新的搜索或分析（`RADAR_TIME_BUDGET` 可调），剩下的留给 20 分钟后的补充分析；关键词顺序每天打乱，时间不够时每天跳过的不同。
- Firecrawl 免费版限速时自动等待重试。
- 2026-10-26 本机真实试跑：20 个关键词 200 条结果，去重后约 170 条，真实需求 3 条，花费 40 积分、约 3 万 OpenAI token。
- 每次运行的积分和 OpenAI token 用量记录在 `lead_radar_runs`。

## 故障排查

| 现象 | 处理 |
|---|---|
| 页面显示“需求雷达暂不可用” | 第 2 步迁移未执行 |
| 立即运行提示“尚未配置 Firecrawl 或 OpenAI 密钥” | 检查第 3 步密钥名称 |
| 运行记录“部分完成” | 管理员展开“搜索关键词”查看错误；单个关键词失败不影响其他 |
| AI 分析失败 | 帖子保持待分析，下次运行自动重试；检查 OpenAI 余额和模型名称 |
| 每天早上没有新运行 | `SELECT * FROM cron.job_run_details ORDER BY start_time DESC LIMIT 5;` 查看定时任务；确认 Vault 密钥与函数 `RADAR_CRON_SECRET` 一致 |
| 真实需求被判成广告 | 在“查看 AI 过滤掉的帖子”中核对，调整关键词或 `logic.ts` 中的提示词 |
