# 整装子单跟踪与员工交接

## 规则
- 默认整单操作，每一项仍保留自己的记录；有例外时勾选几项单独处理。
- **定制项没有业主签名不能下单**，店长也不能跳过，由数据库强制。现货确认规格和数量后可直接下单；施工和赠品没有这一步。
- 业主签名：手机号后四位验证 + 手写签名；可由家人代签，记录姓名和关系。纸质确认单须店长审核通过。
- 签名后、下单前修改：发起新版本，旧签名失效但保留。下单后修改：勾选项目发起改单签名，未签名前这些项不能标记完成；金额有变化时走增减项。
- 子单状态由各项进度自动汇总，不能手动改；客户页只显示状态，不显示厂家和价格。
- 下单记录可更正，但必须写原因，更正前后都留在操作记录里。

## 负责人与业绩
- `renovation_projects.created_by` 现在表示**当前负责人**，权限和付款单电话都跟着它走。
- `renovation_projects.sales_by` 是业绩归属，建项目时写入，交接不改。总览和门店业绩都读它。

## 交接
- 店长或上级发起，接手人确认后才生效；接手人须属于项目门店。生效后原负责人失去该项目权限。
- 账号还有未验收项目时不能停用。紧急离职由店长或上级走“立即转交并停用账号”，不需接手人确认，并标记为强制交接；店长只能办理店员。

## 上线前已存在的项目
上线前已有的清单项都从“待业主签名／待下单”开始。已在系统外下单的，由店长用“登记上线前已下单”补记并写明情况，这个入口不需要签名，且只对迁移时已存在的清单项开放。

## 上线顺序
先在 SQL Editor 执行 `renovation_fulfillment_migration.sql`，核对后再推送前端。新页面依赖新表，顺序不能反。

## 验证
- `RENO_PGLITE_MODULE=... node tests/renovation-fulfillment.mjs`：规则、权限、交接、重复执行。
- `RENO_PGLITE_MODULE=... PLAYWRIGHT_MODULE=... node tests/renovation-fulfillment-browser.mjs`：真实浏览器加真实数据库引擎走完整流程。
