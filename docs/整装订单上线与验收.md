## 已实现

- 原员工后台“新建订单”提供蓝色商品订单、紫色整装入口；订单列表、商品详情及客户商品查单有蓝色文字标签。整装档案和客户整装页使用紫色。
- `portal/renovation.html`：门店／业主／地址／合同编号建档，归档私有PDF，提取并人工核对合同清单、金额、分期及部件质保。
- 所有写入经 `renovation_command`，项目行锁及版本号防止并发覆盖。签约确认需店长或上级；确认后不能覆盖签约快照。
- 按执行分组生成独立履约子订单，原清单编号可追溯；重复拆分不重复建单；记录负责人和进度。
- 原件和验收PDF仅允许新增，不允许覆盖或删除；历史核对版本在审计中保存。员工按本店、区域或管理层范围访问，店员限自己创建项目。
- 全部履约子单完成并上传竣工验收PDF、确认有效验收日期后，质保才起算。按日历年计算，2月29日跨非闰年落2月28日。
- 客户使用独立项目链接查看清单和部件质保；不下发客户电话、银行、原合同路径、内部操作日志。店长可撤销旧链接。

## 主列表与详情展示

主页面只查询并展示 `renovation_projects`，每个整装项目一张主单。进入主单详情才读取并展示履约子单；打开详情时隐藏主列表，点击“返回主订单列表”恢复主单列表。子单默认折叠，展开后登记负责人和进度；未保存核对内容离开前提示确认。子单不进入商品主列表，也不单独计算客户应收。

## 为什么独立建项目和履约子单

既有 `orders.parent_order_id` 用于补件，既有订单参与未付款自动取消／历史删除、仓储和销售报表。整装不能直接混入这些流程。新表为：

- `renovation_projects`：客户主合同及锁定快照；是唯一合同总价来源。
- `renovation_work_orders`：执行分组与原清单关联；无第二笔销售应收。
- `renovation_audit`：创建、核对版本、确认、拆单、进度、验收及撤销客户链接的历史。
- 私有 Storage bucket：`renovation-contracts`，只接受20MB以内PDF。

## PDF识别边界

浏览器用 PDF.js 4.10.38 读取有文字层的PDF。15JR样本按表格位置提取34项收费工程；六项赠品和范本质保规则只有在文件SHA-256与用户提供的原样本完全一致时才应用。未验证或重新签署后的文件不沿用样本质保，需要人工核对／补充；其他合同版式不自动编造清单，可手工填写或导入核对JSON。

样本来源：`HOUZY整装工程合同_15JalanRebab_HZ-RC-20261022-15JR.pdf`。

- 工程合计190,871.25；优惠19,871.25；合同价171,000.00。
- 付款42,750／68,400／51,300／8,550。
- 40项清单按默认执行分组生成14张履约子单。分组在签约确认前可人工调整。
- 背景墙地柜5,600与电视展示柜8,400为不同项，不从本合同扣除7,000。
- 不凭通用条款生成防水工程；厂家期限和赠品质保未知时留空。第25项含标准砖，和旧报价范围不同，提醒审核。
- 自动提取不认定PDF已签署；样本业主／签字／日期空白，不能自动作为有效已签合同。

## 部署顺序

1. 在独立测试项目运行 `supabase/renovation_orders_migration.sql`；该脚本可重复执行，保留数据。
2. 用真实店员、店长、跨店账号验证访问范围、PDF上传和临时下载链接；检查bucket为私有。
3. 使用无真实客户身份的合同副本完成导入、金额核对、锁定、拆单、进度及验收；不要把样本空白签字误认作已签。
4. 记录数据库备份与检查结果，再在目标项目应用迁移，并发布网页文件。未应用迁移时，新入口明确提示尚未部署，商品订单不受影响。
5. 已有客户链接应仅通过授权渠道交给客户；属于持链接可访问，不是实名认证登录。必要时撤销重发。
6. 外部依赖：原站Supabase项目、固定版本supabase-js及PDF.js CDN。网络不可用时明确报错，不把本机数据伪装为已保存云端。

## 当前版本尚未覆盖（业务边界）

- 实际收款／退款已提供独立整装台账并与客户付款进度共用汇总；付款计划不算已收款。发票、银行对账及原商品销售报表尚未接入。详见《整装收款与客户付款进度》。
- 履约子单目前由员工／店长登记负责人和进度；尚未投递到既有厂家、仓库、物流账号，不触发扣库存或采购付款。
- 确认后的原合同仍不可覆盖；现已支持独立登记新增工项／材料，客户电子签署后同步总额、付款及执行单，详见《整装新增工项与材料单》。减少原合同范围和正式补充协议签署／盖章尚未提供。
- 其他版式／扫描合同尚无通用AI/OCR解析，需要人工或核对JSON；未知质保必须人工审核。

这些边界应在下一轮扩展前明确，不能宣称整装财务、供应链或所有合同自动识别均已完成。
